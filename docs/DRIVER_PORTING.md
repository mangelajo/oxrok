# Porting a driver

How a libsigrok hardware driver becomes an oxrok driver module. The
first two ports set the shape (`intronix-logicport`, a command and
response device behind an FTDI FIFO, and `fx2lafw`, a streaming device
with a firmware upload); the serial, HID and SCPI sections came with
the multimeters, the Pico and the Rigol scopes.

## Before writing code

- Read the libsigrok driver for the facts: USB ids, request numbers,
  register maps, rate tables, the order settings are written in, the
  quirks its comments explain. Then write the Rust from those facts,
  with a protocol summary in the module documentation of the driver's
  `protocol.rs`.
- Find the oracle: a sigrok-cli build that has the driver. Its version
  matters; libsigrok 0.5 and 0.6 print some formats differently, and
  oxrok follows 0.6 (`docs/CLI.md`).
- Find the firmware files the driver needs and where sigrok installs
  them; `core::firmware` already searches those directories.
- Decide what stimulus the bench can give the device. Without one, the
  checks are limited to the device's own patterns and idle inputs.

## Where things go

- `src/drivers/<name>`: one module per driver, declared in
  `src/lib.rs`, which also registers it in `register_all`.
- Transport code that other drivers share goes under `src/usb`
  (`Transport`, record and replay), `src/ftdi` or a new module (the
  EZ-USB firmware upload comes with fx2lafw).
- Protocol notes go in the module documentation; usage, firmware,
  permissions and what has been verified on hardware go in
  `docs/DEVICES.md`.

## Shape of a driver

1. `Driver::scan` finds devices with `usb::find_devices` and the
   `conn` scan option (`UsbDeviceInfo::matches_conn`). It returns closed
   devices; `Device::open` claims the hardware. Keep a
   `from_transport(Box<dyn Transport>)` constructor so a replayed
   recording can stand in for the USB device.
2. Settings live in a plain struct on the device. `options`, `get`,
   `set` and `list` map them to sigrok keys. Use the same keys and the
   same list types libsigrok uses, so `--show` and `-c` behave the same.
3. Put the wire protocol in a `protocol.rs` with a `Link` (or similar)
   owning the transport, and keep pure functions pure: register tables,
   divisor math, sample decoding. Those get unit tests with no hardware.
4. Acquisition runs on a thread the device spawns in `start`; it owns
   the link while running and gives it back when done. Send
   `Packet::Header` once the device is armed (a bench starts its
   stimulus when it sees it), then `Logic`, `Trigger`, `FrameBegin` and
   `FrameEnd` as applicable, and `End` last, also on errors. `stop` sets
   a flag the thread polls, then joins it.
5. Avoid time based loop exits where a count of reads does the same job
   (the LogicPort's FPGA init wait). Time based loops replay
   differently from the recording.
6. Match libsigrok's option list, order included, and its default
   values: `--show` prints options in the driver's order, and the
   differential script diffs that output. Channel groups count too
   (fx2lafw has a `Logic` group with no options of its own).
7. Keep the sigrok ids and names of channels, and support
   `probe_names` where libsigrok does, through
   `core::util::parse_probe_names`.
8. Port the C driver's sequence, not only its facts: what the scan
   already does to the device (fx2lafw uploads its firmware there;
   serial-dmm closes the port after the probe), the order of the open
   (fx2lafw reads the version and REVID, then claims), the units its
   sizes count in (one byte per sample even at 16 bits), where a limit
   is checked (serial-dmm after a whole read, not per packet), when a
   request is deferred, buffer sizes and when they are dropped, and
   which errors it tolerates (a failed send, a failed bulk IN counted
   as empty, a port that does not open is no device). Each of these
   was a difference in the transactions the emulator showed, and none
   would have shown in a fixture recorded from oxrok itself.

## Testing

- Unit tests for the pure parts.
- Without the hardware, a device model for the USB/IP emulator
  (`emu/src/models`, `docs/USB.md`), written from the C driver's view
  of the device with pedantic checks on what the host may send;
  `tools/diffcli.sh --emu` then compares output and USB transactions
  under both tools.
- A recorded session per important path, replayed in CI. For a driver
  with an emulator model, mark one or two representative cases (a
  capture; for a streaming device one with a trigger or frames)
  `emu_case ... --record` and bless them: the fixture and the output
  land in `tests/fixtures/DRIVER/emu-*`, and `tests/emu_replay.rs`
  runs oxrok on each with `OXROK_USB_REPLAY` or `OXROK_HID_REPLAY`;
  add the driver to its `RECORDED` list. No hand written fixtures for
  drivers with a model. Without a model, `OXROK_USB_RECORD=file oxrok
  -d <driver> ...` (or `OXROK_HID_RECORD`, `OXROK_SERIAL_RECORD`)
  records on the hardware, and the same command with
  `OXROK_USB_REPLAY=file` (`OXROK_HID_REPLAY`) replays it; library
  tests build the device with `from_transport(Replay)`. Keep the
  expected output next to the fixture. Large payloads are stored as
  digests, so a firmware upload is one line. See `docs/USB.md` for the
  format.
- Writing a device model, model the device, not the comparison. A
  behaviour invented to make the runs repeatable (a CP2110 that only
  sends after its FIFO is purged, four packets at once) made the cases
  pass while hiding what a real stream does, and made the evidence for
  an oxrok change circular. Pace by counts the host drives (polls,
  submissions), never by wall time, and say in the model which of its
  habits are emulation artifacts.
- Give models fault options, off by default so the goldens stay put:
  a STALLed request, an empty, short or garbage answer, an unplug.
  The error paths are where the two drivers differ most, and a
  device can really produce every one of them.
- Take device facts from the firmware source or a recording, never
  from memory: fx2lafw's `.dw` is big endian, so its bcdDevice is
  0x0001, not the 0x0100 the source seems to say.
- When a full case differs, find out which side is wrong before
  touching either. If it is libsigrok (a crash, a check that logs and
  carries on), do the sane thing and keep the case as an
  `--oracle-bug` case, which fails once upstream fixes it. When
  libsigrok is wrong but sigrok-cli still exits 0 (fx2lafw's soft
  trigger with the USBee AX's A0 enabled, its trigger on A0, the csv
  output's mixed columns), make it an `--oracle-differs` case with the
  C lines quoted: oxrok is pinned to its goldens, sigrok-cli's output
  is kept as `SLUG.oracle`, and the case fails once the two agree.
- Run a port's cases with `--no-oracle --emu-model MODEL` as well, as
  CI does: oxrok then runs alone on a freshly attached device (the
  harness unbinds vendor-interface drivers first, so a kernel driver
  bound as on a user's machine is still shown by no case). A normal
  run hides that state, because sigrok-cli goes first:
  libftdi detaches `ftdi_sio` and never gives it back, so ftdi-la
  passed every full case and failed 30 under `--no-oracle` until the
  harness learned to unbind vendor-interface drivers before oxrok.
- A model accepts what the C driver really sends whenever a real
  device could not refuse it (a command with no answer, a field wide
  enough to hold it): document it as a C habit and make it a case.
  Flagging it leaves the path without a case (pipistrello-ols'
  oversized counts, hantek-4032l's PWM 4096 and capture ratio 100).
  Flag only what the device would reject or what no C path sends.
- Every pedantic check gets a unit test that makes it fire. A review
  of lecroy-logicstudio found 20 of its 50 checks never fired in any
  test, and two others were wrong (accepted at any time where the
  driver sends one exact value).
- A change to what every model sees (`emu/src/usbip.rs`, a shell, the
  harness) reruns every model, not only the one it was made for.
  saleae-logic16's port rounded bulk IN reads up to whole packets, and
  the saleae-logic-pro model, merged the same day from another branch,
  then flagged all of its 79 capture cases.
- After a firmware upload the device comes back at another address,
  and a case that selects by `conn=BUS.ADDR` must use the new one
  (read it from sysfs); the session's first address then matches
  nothing, and a driver that lists everything on a non-matching `conn`
  (saleae-logic-pro) passes such a case without testing selection.
- `emu_case` starts with a reset, which re-attaches a device whose
  descriptors the previous case changed (boot loader against firmware).
  A helper that holds the interface before the case (the claimed-
  interface cases) needs the previous case to end with the same
  descriptors, or its claim is on the device that left.
- Read the gcov report of the C driver (`diffcli.sh --gcov`) and
  account for every unreached line: a case to add, a fault option to
  add, or a reason (sigrok-cli cannot ask, the platform never does it).
  The shared transport files (`serial_hid*.c`, `ezusb.c`, `usb.c`)
  hold bugs too.
- An oracle diff while libsigrok still has the driver: the same capture
  through sigrok-cli and `oxrok`, compared after the header line. The
  `bits` and `csv:trigger=true` outputs cover sample values and the
  trigger position.
- Hardware in the loop checks in `hil/oxrok-hil` when a stimulus source is
  available. They should run through the library, not by parsing CLI
  output, and print one PASS/FAIL line per check.

## Streaming devices

The fx2lafw driver is the model: open a `bulk_in_stream` sized for
10 ms of data per transfer and about 500 ms in flight, send the start
command, then loop on `next` until the sample limit or the stop flag.
`core::SoftTrigger` matches a `Trigger` on the host, and
`PreTriggerBuffer` keeps the capture ratio's worth of samples before
it. Firmware uploads use `ezusb` during the scan, as libsigrok does;
open then retries until the device is back, finding it by its port
path (`UsbDeviceInfo::ports`).

## Serial devices

`serial` is the counterpart of libsigrok's `serial.c`: a `Port`
trait (read with a timeout, write, parameters, RTS and DTR), the
`serialcomm` syntax in `Params::parse`, and `Recorder`/`Replay` with a
text fixture like the USB one. A driver takes `conn=` and an optional
`serialcomm=`, opens the port with `serial::open` (which records
when `OXROK_SERIAL_RECORD` is set) and keeps a UART it probed with
(sigrok closes it after the scan and opens it again; reopening toggles
the handshake lines, and adapters such as the CP2102 on the ESP32 reset
their board on that), flushing its input when the device takes it
over, as sigrok's `serial_open` does on every open. A serial over HID
cable has no handshake lines and is closed after the probe and
reopened, as in sigrok, which sends its line parameters again. Packet based protocols are
pure parsers in `dmm` (`valid` and `parse` on a byte slice), so
each one tests against packets written from its layout without a
meter. A validity check should demand a recognised function, not only
a terminator: fourteen bytes ending in CR LF is also a boot banner.

Serial over HID cables (libsigrok's `serial_hid*.c`) are `Port`s too:
`serial::hid` holds one `Chip` per adapter with its USB ids,
report framing and parameter report, over the blocking `HidDevice`
trait of `hid`. A port name starting with `hid` goes there from
`serial::open`, so a driver supports every cable at once. The
report conventions are hidapi's (first byte is the report id, 0 when
unnumbered), which is what the C code was written against; keep the
byte sequences identical to it rather than reasoning from the chip's
datasheet. `hid::SharedFake` scripts a device for tests.

## SCPI devices

`scpi` is the counterpart of libsigrok's `scpi.c` and the
`scpi_*.c` transports. A driver holds a `Scpi`, asks with
`get_string`, `get_bool`, `get_int`, `get_f32`, `get_block` and sends
settings with `send` (plus `get_opc`, or a pause on the DS1000). The
resource strings are sigrok's (`usbtmc/BUS.ADDR`, `tcp-raw/HOST/PORT`,
`tcp-rigol/HOST/PORT`, a serial path); `scpi::scan` probes every
USBTMC device when there is no `conn=`. USBTMC needs the interface
class and endpoints, which `usb` now reports before and after
opening (`UsbDeviceInfo::interfaces`, `Transport::interfaces`).

Fixtures sit above the wire: `OXROK_SCPI_RECORD=FILE` writes the
messages sent and the responses collected (`send "..."`,
`response "..."` or `response hex ...`), and `record::Replay` answers
them back in order. A hand written fixture is a readable statement of
the command sequence a driver must produce, so write the first one
from the C code before the instrument is on the desk, then replace it
with a recording. Long downloads use `read_begin`/`read_data` on the
`Scpi` directly; `get_block` handles the common IEEE 488.2 case.

## Beyond libsigrok's keys

A device may do more than libsigrok's key set covers. Two hooks:

- `Key::Custom(&'static CustomKey)` in the device's option table. The
  key has an id, a name, a description and a value kind; `-c`, `--get`
  and `--show` resolve it through `core::option::resolve_key`, so it works
  like a well known key. Keep ids lower case with underscores, keep the
  value strings short (`off`, `active-high`), and put a read that takes
  time (a measurement) behind a `GET` only key.
- `Device::trigger_features()` says which trigger extras the hardware
  has (counts, consecutive counts, durations, value ranges, or and and
  combines, a stage limit). The `-t` parser and `set_trigger` check a
  trigger against it with `Trigger::check`, so the error names the
  unsupported feature before anything is written to the device.

When a register's behaviour is not pinned down by the protocol notes,
let the bench decide: the LogicPort's duration counter turned out to be
cumulative without the consecutive flag, its duration trigger lands one
sample later than an edge trigger, and inverted inputs come back
inverted from the sample memory. Each cost one bench run to find and
would have cost a user a long afternoon.

## Order of work that paid off

1. Transport first: enumerate, open, claim, run the pin-safe requests,
   record a fixture. For the LogicPort these were the FTDI requests
   that drive no pin; for an FX2 it is the version request.
2. The pure parts with unit tests: tables, encodings, sample decoding.
3. A first capture through the CLI with `-l 4`, then the oracle diff.
4. The bench checks, ported from whatever suite existed for the C
   driver.
5. Record the fixtures last, once the sequence of calls is stable, and
   write the replay tests from the output printed during the recording.

## Pitfalls met so far

- Protocols with sequence numbers in their replies cannot have polls
  invented by the replay; make the loops count reads.
- The FTDI status bytes come with every USB packet, not every read;
  strip them per `wMaxPacketSize`.
- A bench that reads CSV sees values compacted to the enabled channels;
  one that reads packets sees all channels. Compact explicitly.
- A device clone keeps the uploaded firmware until it is power cycled,
  so the upload path runs once per plug in. Verify it before anything
  else, and remember it is not re-run by later captures.
- Fixture tokens must not be ambiguous next to hex: `00*59` followed
  by `3160` read as a run of 593160. Runs are `00{59}` now.
- Streaming devices lose data in the gap between two blocking reads;
  use `bulk_in_stream`, which keeps transfers queued.
- A replay invents nothing: when the live run polled n times and the
  replay polls m times, the fixture layer repeats or skips polls only
  for reads without sequence numbers. Everything else must be
  deterministic in the number of calls.
- libsigrok has habits worth not copying: the demo ignores triggers,
  fx2lafw wraps a single capture in a frame and re-arms before
  stopping, the binary input ignores the size suffix. The emulator
  found more: fx2lafw crashes on a frame that ends on a transfer
  boundary, opens a firmware of the wrong major version, and takes its
  soft trigger's sample width from all channels rather than the
  enabled ones; `serial_hid.c` converts a found cable's path twice, so
  only `raw=` names open; `serial_hid_cp2110.c` reads `serialcomm`'s
  flow control with libserialport's numbering. Do the sane
  thing, document the difference in `docs/CLI.md`, and exclude or
  filter the case in `tools/diffcli.sh`.
- The C drivers' arithmetic and error paths are where a port must not
  follow the C line for line. The EZ-USB models found each kind:
  - integer widths: kingst-la2016 truncates its clock divider to 16
    bits (3051 Hz becomes 12.5 MHz), dslogic computes a 90 % bound in
    32 bits and gets about 10 % on the large boards;
  - an error read as data: kingst-la2016 returns a failed register
    read as 0xfff5, whose idle bit starts a download;
  - arithmetic before validation: saleae-logic16 divides 0 by 0 for a
    rate it would refuse a few lines later;
  - uninitialised bytes on the wire: dslogic sends a struct field it
    never set; a port sends a defined value (0) and says so;
  - transfers freed in flight or left dangling: kingst-la2016's error
    exit frees queued transfers and libusb aborts, dslogic frees a
    trigger transfer it still counts as submitted; in Rust the stream
    owns its transfers and dropping it cancels them;
  - errors retried for ever: hantek-dso, hantek-6xxx after its flush,
    and the PICkit2 on a vanished device never end a capture; a port
    ends it on a disconnect (`Error::Disconnected`) and after a bounded
    number of failures, as fx2lafw's `MAX_EMPTY_TRANSFERS` does;
  - readbacks that do not match the setting: dslogic's `clock_edge`
    is always "rising", hantek-6xxx's `coupling=DC` reads back AC on a
    DC-only board; a port answers what was set.
  `docs/DEVICES.md` lists, per device, what its model found; read it
  before porting that driver.
- sigrok-cli's own parsing limits what a comparison can show: sizes
  with a fraction lose their suffix (`12.5M` is 12 Hz), floats are
  parsed in single precision (20000001 is 2e7), voltages only as whole
  V or mV, and it has no SIGINT handler, so a Ctrl-C case can only
  check oxrok (`--oracle-bug`).
- A claim that libsigrok has a bug needs the C lines quoted and, where
  a case can show it, the case. The reviewers of the second batch
  corrected the stated cause of about a third of the claims (a
  use-after-free taken for a hang, a divisor named wrong).
- Do not run a repository script with guessed arguments: an older
  `tools/attribution.py` took `--help` as its source directory and
  rewrote every header. It now needs `--only FILE` or `--all` and has
  `--check`.
- The user's `-l 4` log is the first debugging tool: keep the debug
  messages at the protocol steps (resync, image probe, readout window,
  transfer plan), and filter library noise out of it.
- macOS after a firmware renumeration: the device's configuration is
  active and the descriptors list the interface, yet claiming it fails
  with "interface not found". libusb never shows this because it sets
  the configuration on every open; the nusb backend now does the same
  when a claim fails, then reopens the device. A device that uploads
  firmware needs a power cycle to test this path, not a replug of the
  cable alone if the board keeps power.
- A bench driven over a serial port: opening the port resets an ESP32
  (DTR), so state set in one process (pin maps, levels) is gone in the
  next. Keep one connection open across an experiment; the bench tool
  has `--delay` for that. The symptom was a capture of boot glitches
  and a sequence played on the wrong pins.
- Ad hoc comparison loops in zsh: an unquoted `$var` stays one word, so
  both tools get a mangled command, both print nothing, and the
  outputs compare equal. Count the oracle's lines in every comparison
  and treat zero as a failure; use `${=var}` or `sh`.
- Check the kernel's quirk lists before choosing a transport: the
  PICkit2 is on the HID ignore list, so on Linux usbhid never binds it
  and there is no hidraw node; it takes raw interrupt transfers there,
  as libsigrok does.
- Claim an interface plainly and detach a kernel driver only when the
  claim says busy, as libsigrok's `libusb_kernel_driver_active` dance
  does. Detaching unconditionally reattaches on release a driver that
  was never bound, and its probe sends requests of its own (usbhid
  read the PICkit2's serial number again).
- Keep one call sequence on every platform and put a platform's needs
  in the transport backend (Windows wants a claimed interface before a
  control transfer): a `cfg!(windows)` step in a driver breaks every
  replay fixture on that platform.
- A recorded fixture is a recording: do not edit it to match a new
  call order. Make the replay tolerant of steps that are no transfer
  (a claim), or add a hand written fixture next to it.
- A bulk stream resubmits a transfer when the next one is asked for,
  as a libusb callback resubmits at its end; resubmitting before
  handing back the data completes one more transfer after a stop.
- `--get` prints what `g_variant_print` prints: quoted strings,
  doubles with `%.17g` and a `.0`, tuples as `(1, 1000)`.
- C's float to int conversion of an infinite reading is undefined;
  x86-64 gives INT_MIN, so an overload golden (`inf MΩ`) is the x86
  answer, and the Rust code must not panic on it.
- A driver's scan must reach the device through `usb::list_devices`
  and `hid::list` on every system when a replay variable is set: the
  PICkit2, which takes the HID API off Linux, takes the USB path
  whenever `usb::replaying()` says a replay file stands in.
- A replay answers at once, so a driver that waits on wall time (a
  retry after 500 ms, a scan's 3 s) spins through instant timeouts
  until that time has passed, and one that waits for ever (the PICkit2
  until its trigger) never ends: the replay test kills oxrok after 60 s
  and fails the fixture.
- Run the whole test suite before committing, not one test file; a
  changed listing or default breaks goldens elsewhere. CI runs clippy
  on the current stable Rust, which may be newer than the local one,
  and on Windows, where checked out text files would get CRLF without
  the `.gitattributes` rules.

- A driver on libftdi talks to libftdi, not to the chip: port the
  library's behaviour, not FTDI's application notes. libftdi's divisor
  rounds differently from AN_232B-05 (the H chips switch to the 120 MHz
  clock from 733 Bd, the AM has its own `ftdi_to_clkbits_AM`), it
  multiplies bit-bang rates by 4, refuses rates more than 5 % off, and
  reads in 4 KiB transfers whose surplus a later read gets.
  `src/ftdi/libftdi.rs` does this for the libftdi drivers; check its
  divisor against the libftdi binary across chips and rates.
- Error output is part of the port: keep libftdi's codes and strings,
  and log the C driver's own message, so a scenario's `--filter` only
  has to map oxrok's log prefix and `sr_strerror()` wording.
- A field the C driver advertises but never sets (ftdi-la's
  `sdi->conn`) is a bug to fix, not copy: answer it, and mark the cases
  `--oracle-differs` / `--oracle-bug` with the C lines.
- Watch C integer widths: a 64 bit config value stored in a `uint32_t`
  (ftdi-la's `cur_samplerate`) silently wraps; keep 64 bits and pin the
  case with `--oracle-differs`.
- A C driver runs everything in one thread; a port whose acquisition
  thread owns the transport must decide what a set during a capture
  does (send it through the thread, or refuse). Never store it unsent.
- The C may ignore a return value (`ftdi_set_bitmode` in
  dev_acquisition_start); follow it, and log at debug.
- libusb's detach leaves the kernel driver detached; nusb's
  detach-and-claim reattaches on release. The device then sees the
  kernel driver's probe after oxrok, which the harness cannot show
  because sigrok-cli always runs first. Document it.
- The bus.address changes when a variant's descriptors re-attach the
  device: mask it generically there, but on the first attach let the
  harness's exact `conn=$EMU_USB` rule (and exact filters for `--show`
  and `--get conn`) pin it.
- Keep build dirs and TMPDIR off a quota'd /tmp: a debug target of the
  whole workspace is over 2 GB, and a full `--emu` run on a /tmp out of
  quota fails other models' oracle cases.
- nusb submits IN transfers only in whole packets, so a C driver that
  reads short answers with exact-length URBs (libusb allows it) cannot
  be matched URB for URB. The emulator rounds a bulk IN to the packet
  size for the model and the log, because that is what the device sees
  on the bus. The URB's own length still decides the outcome on the
  host: an answer longer than the URB is a babble (-EOVERFLOW), and the
  server reports it so.
- Before porting a driver-level check of an option, look for a generic
  check in libsigrok's hwdriver.c (`sr_config_set()`, `check_key()`): it
  may refuse the value first, and then the driver's bug cannot be
  reached.
- libsigrok's session stops the device whose start failed
  (session.c:831-835). A driver whose stop sends commands shows them
  after every refused start, so the port sends them as well.
- A by-address case on a board that renumerates cannot run full: the
  first tool's upload moves the device, and the second tool cannot reach
  EMU_USB. Start the session with the firmware running.
- Stderr cases need the log prefixes normalised ("sr: DRIVER: " against
  "oxrok: LEVEL: MODULE: "); log the C's message texts verbatim.
- A driver whose capture sigrok-cli cannot start (lecroy-logicstudio has
  no limit or continuous key, so every capture flag is refused before
  acquisition) has only its scan and options under the oracle; its
  capture side rests on the model's unit tests until the harness can
  drive libsigrok directly.
- A device that always dumps its whole memory still lets a port honour a
  limit on the host. Keep the transactions identical and cut the output.
  Then add cases whose limit equals the memory, so every sample of both
  tools is still compared as a full case.
- A driver whose readout is megabytes cannot record a capture fixture.
  Record a fault case that ends early (`in-stall=N`) and say that replay
  does not check samples.
- A wall-clock deadline in the C driver cannot run as a full case: its
  poll count varies from run to run. A port can count reads instead, but
  a count alone is right only at one poll time. Pace each poll to a
  minimum interval, make that interval injectable for tests, and state
  what is left: a slower device stretches the wait.
- A stop that joins an acquisition thread must never run on the thread
  that empties the queue it blocks on. `Session` now drains while it
  stops. A test for this has to make the queue really full (stop
  reading, at a high rate), or it passes without the fix.
- An `--oracle-bug` case must mean the C driver fails by itself. A
  sigrok-cli that fails only because the case's timeout killed it is not
  a bug, and an upstream fix would not flip the case.
- An `--oracle-differs` case can differ on output size alone and pin
  nothing about the behaviour it is named for. Check that the golden
  shows it: hex prints `T:` only with a full 192-sample line.
- `--oracle-bug` `.oracle` goldens keep sigrok-cli's raw stderr, so such
  a case must not run at `-l 4`, whose timestamps change every run.
- `--unplug out=EP:N` fires after the Nth transfer completes, so it
  cannot fail that transfer. To fail the first bulk OUT, unplug after
  the last control write before it (`out=0:5` here).
- A sed `--filter` that normalises log prefixes and also folds repeated
  lines with `N` must match `(^|\n)` with `g`, or the second line
  reaches the comparison unnormalised.
- Check C line numbers against the source before quoting them.
- A model written from the C driver's comments cannot prove those
  comments wrong. Before calling a C count a bug, ask what else could
  make it right, and give the model an option for that reading. Here the
  +1 looked right only because the model's stop register always sat on a
  cluster boundary.
- Don't refuse what the C driver sends when nothing shows the hardware
  rejects it. Warn instead: a refusal can break a capture that works on
  real hardware.
- `--filter` is not additive in `emu_case`: only the last one applies,
  so `--filter "$A" --filter '...'` silently drops the first. Join the
  expressions with a newline.
- A driver that uploads on every capture needs its firmware in the
  replay: `tests/emu_replay.rs` writes the stand-ins itself. Check a
  fixture's size before keeping it; a memory readout stores its answers
  as hex, so record a sparse capture.
- Scenario variables share one function scope. A new filter named R
  would have been overwritten by the existing `R=captureratio=100`.
- An `--unplug` case's replug rebinds kernel drivers before oxrok's run.
  oxrok's reattach on release then adds control transfers, and unplugs
  counted in transfers fire earlier. The harness unbinds before oxrok in
  those cases.
- A check of a cap in `sigrok-cli` (`maybe_config_get`) covers unlisted
  keys too: use the whole condition, per scope.
- A short-read fault needs a check beyond "differs from the oracle".
  Comparing oxrok's output with the same capture without the fault shows
  the fix restores the stream.
- A `sed` `$` address in a scenario filter breaks if the tool's last
  line varies. Match the final line by its text instead.
- libftdi's `ftdi_usb_open_dev` leaves the error string "all fine",
  which a later failed close prints.
- A device's own firmware source outranks a model built from the driver:
  look for it before accepting a model's assumed semantics. The model's
  trigger timing made two `--oracle-differs` cases circular, since the
  driver's "bug" was measured against assumptions in the model.
- A fix in a shared layer changes other ports' results. The `close` fix
  showed in scanaplus and chronovu, whose earlier matches relied on
  nusb's release never failing.
- sigrok-cli does not close the device after a refused start
  (session.c:896-901) while oxrok does: filter that line and say why.
- libftdi's `ftdi_usb_close` fails on a device that left, and keeps the
  previous error's message; nusb's release reports success there. Track
  the disconnect in the layer that mimics the library.
- A driver's per-transfer timeout is protocol, not just error handling:
  "a timeout is not fatal, take what arrived" needs a stream that gives
  the partial data back (`bulk_in_stream_timed`). A transfer sized for
  the fastest rate takes minutes at the slowest.
- Run the same `-O format:width=` against sigrok-cli for edge widths: a
  narrow hex width shows C's integer promotion.
- `stop` must not join a thread that may still send packets; `close`
  joins.
- A golden case on an interrupt needs a known count: hold transfers
  after N, or the number before the signal depends on timing.
- A divider cast to a narrower type can truncate to 0 as well as to a
  wrong value. Check whether the exact boundary value is reachable and
  whether anything divides by the result: 800 MHz / 12207 is the one
  such rate here.
- A log line can be a transaction: libsigrok's spew-level register dump
  reads the FPGA only at `-l 5`, so the port checks
  `log_enabled!(Trace)` to send the same requests.
- `--oracle-differs` compares sigrok-cli's stdout through the same
  `--filter`, so a stderr filter must keep a stdout line or the case
  fails with "no output from sigrok-cli".
- Filters run after the emulator's sed: normalise oxrok's log prefix to
  `sr: DRIVER: ` once and build the other filters on it, so an
  unanchored match does not also catch the CLI's own final error line.
- A driver that loads firmware on every open can only replay with the
  same bytes: `tests/emu_replay.rs` writes the stand-ins itself.
- A `--record` case keeps raw stdout, so it must use an output without
  dates (bits or hex, not csv).
- A wait with no model event point can still be interrupted
  deterministically: `--interrupt out=0:N` on the last control write
  before the wait, with no model change.
- When a C driver loads the wrong thing and reports another, prefer a
  fix that keeps the transactions. It keeps failing cases full, because
  `--oracle-differs` needs sigrok-cli to exit 0.
- `EMU_OPTIONS` needs `-o` before each option.
- Read a device's header packet with a plain read rather than a stream
  of one: the libusb backend's stream reads ahead on its own thread, so
  samples are lost when it drops, silently with rc 0.
- To check a libusb build, set `OXROK_USB_BACKEND=libusb`; `--features
  libusb` alone still defaults to nusb.
- A case's `--samples` must reach the fault it tests: the cut 3ch case
  first stopped before the cut, and "oracle fixed?" caught it.
- `--digest` on csv needs `csv:header=false`, because the header holds
  the date. `-O binary` needs `--keep-header`, or the header strip
  removes everything and the digest is that of nothing.
- On an unflashed board, a stderr case must filter "Failed to open
  device": a retried open logs it depending on timing, under both tools.
- A C "bug" whose only ground is a model that implements the C's own
  comment is not proven. Look for the device's firmware source first;
  keep the C's behaviour until a recording says otherwise, and never
  turn an inference into a refusal.

## Porting a decoder

The decoder runtime mirrors libsigrokdecode's Python API, so a native
decoder is written from the protocol and the `pd.py` is the oracle for
classes, rows, texts and sample ranges. What mattered for uart, i2c and
spi:

- Keep the class indices, rows and binary classes of the upstream
  decoder, including its quirks that selections depend on (uart tags
  stop bits with the parity-ok class).
- `wait` semantics: the first sample is examined in place, edges need a
  previous sample, `skip` counts from the current sample, unassigned
  channels read 0xff. Stacked decoders get their items synchronously,
  before the lower decoder continues, which fixes the output order.
- Compare at `-l 4` (sample ranges, class names, all texts) against
  sigrok-cli on a synthetic capture first, then on a bench capture.
- The Python host sets `options`, `samplenum` and `matched` on the
  instance, not as properties of the base class: decoders define class
  attributes of the same names (`options` is their option table) and
  an instance attribute is what shadows them.
- In a module that imports `crate::core::Result`, write
  `std::result::Result::ok` in iterator chains; the alias changes the
  meaning of `Result::ok`.
